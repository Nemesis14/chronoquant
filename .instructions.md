# ChronoQuant Copilot Instructions

## Project Context
ChronoQuant is a **real-time ML trading signal prediction system** for Binance. It fetches live OHLCV data, calculates technical features, runs trained logistic regression models, and generates LONG/SHORT trading signals via a Tkinter UI.

## Communication Preferences

### Language
- **Primary:** English (US)
- **Corrections:** Always correct English grammar/phrasing and highlight new/overlooked expressions
- **Style:** Concise, technical, direct

### Documentation
- **Diagrams:** Use Mermaid (graphs, sequence diagrams, flowcharts)
- **Format:** Markdown with clear sections
- **Approach:** Concise explanations without redundant prose

## Architecture Review Pattern

When asked to review/document the project, follow this workflow:

1. **Analyze repository structure** — Read key files to understand:
   - Entry points (main_app.py)
   - Core modules and their purposes
   - Data flow and dependencies
   - Configuration structure

2. **Create ARCHITECTURE.md** with sections:
   - Overview (1-2 sentence summary)
   - System Architecture Diagram (Mermaid: graph showing data flow)
   - Core Modules Table (file → purpose mapping)
   - Data Flow Diagram (Mermaid: sequence or flow diagram)
   - Signal Logic (Mermaid: decision tree/flowchart)
   - Configuration Structure (JSON examples)
   - Key Processes (4-5 main workflows)
   - Scope (What it does / doesn't do)
   - Deployment instructions
   - Tech stack
   - Related resources (ANALYSIS.md, notebooks, etc.)

3. **Preserve precision:**
   - Reference actual signal thresholds from ANALYSIS.md (e.g., ±0.0139, ±0.0142)
   - Mention specific models (lg_l_rw240_p90_base_sm, lg_s_rw240_p90_base_sm)
   - Link to relevant files in documentation

## Key Project Facts

| Element | Detail |
|---------|--------|
| **Main Loop** | 60-second worker cycle (configurable) |
| **Data Source** | Binance API (1-min candles) |
| **Models** | 2 logistic regression models (long + short) |
| **Features** | RSI, ROC, SMA ratio, Bollinger Bands (7-8 total) |
| **Signals** | LONG (≥0.0139), SHORT (≤-0.0142), NEUTRAL (between) |
| **UI** | Tkinter with live logs and prediction plots |
| **Build Tool** | PyInstaller (→ .exe executable) |
| **DB** | SQLite3 (OHLCV, FEATURES, PREDICTIONS tables) |

## English Language Correction Workflow

**When the user's request contains non-standard or non-native English phrasing:**

1. **Interpret the intent** — Understand what the user is asking
2. **Correct and repeat back** — Show the properly phrased version in standard English
3. **Stay close to original** — Preserve the user's meaning and intent; only modify grammar/phrasing
4. **Highlight improvements** — If helpful, note alternative expressions or clarifications
5. **Example format:** 
   - User: "i want create file with data"
   - Response: "You want to **create a file with data**. [proceed with task]"

This helps the user learn proper phrasing while accomplishing their task.

## Markdown File Auto-Rendering Workflow

**When the user asks to create or modify a `.md` file:**

1. **Create the file** — Use `create_file` tool
2. **Auto-render with Quarto** — Immediately run quarto rendering in the terminal:
   - Command: `quarto render [filepath] --to html`
   - Check if Quarto is installed; if not, suggest installation
3. **Auto-open HTML output** — Immediately after successful rendering:
   - On Windows: `start [output_filepath].html`
   - On macOS: `open [output_filepath].html`
   - On Linux: `xdg-open [output_filepath].html`
   - Alternative: Use VS Code `open_browser_page` tool to display in integrated browser
4. **Confirm rendering** — Show preview message with file path
5. **Example:**
   - User: "Create a plan.md file"
   - Action: Create file → Run `quarto render plan.md --to html` → Auto-open plan.html → Confirm in chat

This ensures markdown documentation is always rendered and immediately viewable.
